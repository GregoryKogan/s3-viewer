Everything you would otherwise download to check

Most S3 tools show you a file name and a size. This one shows you the file.

Media, without waiting

Images, audio and video are streamed from S3 with HTTP range requests. Playback starts on the first bytes; seeking fetches only what you seek to.

PDFs you can actually read

Rendered with pdf.js: zoom, fit to width, page navigation. Pages load on demand instead of pulling the whole document.

Text, highlighted

Markdown renders with a sanitised preview and a raw toggle. Code is highlighted for about 30 languages, JSON is pretty-printed, CSV becomes a table.

Parquet as a table

Columnar files are read properly — schema, columns and the first rows — instead of being treated as opaque bytes.

Files with no extension

SSH keys, .pub, .pem, dotfiles and extensionless files are shown as text when the bytes say they are text, rather than being labelled binary.

Large folders stay responsive

Listings stream in pages and the table renders only the rows on screen, so a prefix with a hundred thousand objects scrolls like any other.

Honest about what it can do

A probe tells you whether these credentials can list, read, write and delete. Per-connection read-only mode blocks every write in the interface.

Transfers you can steer

Every upload and download reports progress per file; a transfer that fails can be retried or cancelled without leaving the app. When an upload would overwrite an object you choose: replace it, replace all, or skip the existing ones. Selecting several files downloads them into one folder.

Copy and move without a round trip

Send a selection to another folder, or to a different saved connection, with a server-side copy. A file can travel between buckets without passing through your disk, and the same menu handles folders and single objects.

Bring the credentials you already have

Paste the credentials JSON you already use, or a boto3 client snippet straight out of your code, and the app builds the connections from it — secrets are encrypted before anything is written to disk.

It updates itself

On launch the app checks GitHub Releases and offers the new version, which it installs and restarts into. The download is checked against a signing key built into the app, so a tampered bundle is refused rather than installed.

Keyboard first

←/→ move between the connections, the list and the preview; ⌘L pastes an s3:// address, ⌘D downloads, ⌘⇧C copies S3 URIs, ⌘A selects all, Shift+click covers ranges. Every action is reachable without a pointer; the row menu is on ⇧F10.

Install

  1. Download the disk image and open it.
  2. Drag S3 Viewer into Applications.
  3. Add a connection: the fields mirror a boto3 client one to one.

Linux releases are a .deb and an AppImage in the same release. On Linux there is an extra step before that: nothing — they just run.

First launch on macOS

The app is not notarised by Apple yet, so macOS will say it cannot verify the developer. That is expected. Allow it once, one of two ways:

System Settings → Privacy & Security, scroll down, press Open Anyway.

Or remove the download flag from Terminal:

xattr -dr com.apple.quarantine "/Applications/S3 Viewer.app"

You will see the same prompt once per new version until the build is signed with an Apple Developer ID. Verify what you downloaded against the .sha256 file published with each release.

Where your keys live

  • Secret keys are sealed with XChaCha20-Poly1305 before anything is written to disk.
  • The master key lives in the OS keychain, not in a file.
  • The config file is 0600 inside a 0700 directory, written atomically.
  • No telemetry. The only background request is the update check against GitHub Releases; everything else goes to the endpoint you configure.

What it connects to

  • Any S3-compatible endpoint, not just AWS.
  • Signature V4, or legacy V2 where the service needs it.
  • Path-style or virtual-host addressing.
  • Both checksum switches, for services that need the other behaviour.
